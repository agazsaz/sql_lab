# sql_lab

## Структура файлов
Все материалы лабораторной работы находятся в директории **[db_lab](./db_lab)**:
* `my.cnf` — конфигурационный файл MySQL
* `my_actions.log` — лог выполненных SQL-запросов
* `index_dump.sql` — дамп базы данных

## Результаты выполнения работы

В ходе работы были проанализированы планы выполнения запросов с помощью команды `EXPLAIN` и исследовано влияние индексов на выборку данных.

1. **Индексирование поля `amount`**
До создания индекса запрос выполнялся с полным сканированием таблицы (`type: ALL`). После создания индекса `idx_amount` план выполнения изменился на `type: range`, что подтверждает успешное использование индекса для поиска по диапазону.

2. **Влияние функций на использование индекса**
Использование функции `YEAR()` в условии `WHERE` (например, `YEAR(order_date) = 2026`) приводит к отказу от использования индекса и полному перебору строк. При переписывании запроса через диапазон дат (`order_date >= '2026-01-01' AND order_date < '2027-01-01'`) база данных успешно применяет индекс `idx_date`.

3. **Составной индекс `(status, amount)`**
Созданный индекс `idx_status_amount` работает по правилу левого префикса. Он эффективно используется при фильтрации по полю `status`, а также при комбинированном поиске по `status` и `amount`. Однако при поиске только по полю `amount` данный индекс не применяется.

4. **Покрывающий индекс `(customer_id, amount)`**
При использовании индекса `idx_cover` для запроса с агрегацией `SUM(amount)` в плане выполнения появилась отметка `Using index`. Это означает, что был выполнен Index-Only Scan — данные были взяты непосредственно из индекса без обращения к самой таблице.
